THE SESSION MODEL

Reasoning stays in the room.

ASTRA is the orchestration layer around the coding agent you already use. It keeps the handoff legible without asking your team to trust a black box.

A

One agent. The whole pipeline.

The agent that wrote the product intent keeps its reasoning context through architecture, program design, graph planning, and execution.

B

Every transition is inspectable.

The ledger and artifacts are the source of truth. An announced-but-unrun gate cannot masquerade as complete.

C

Human approval is a feature.

ASTRA never enables unrestricted auto-run flags. Risky commands pause for an explicit response.

FREQUENT SIGNALS

Questions before the first run.

The short version: ASTRA is a process and evidence layer for the agent you already have.

Is ASTRA OS another coding agent?

No. It is a portable harness around the coding agent you already use. ASTRA adds the gated process, artifact validation, bounded roles, and review surface.

Which agent CLIs can ASTRA drive?

The bundled adapters cover Pi, Claude, Droid, OpenCode, Hermes, and Codex. Pi runs through its SDK; the other adapters spawn their installed CLIs.

What happens when a gate is not ready?

ASTRA names the missing or invalid artifact, stops the transition, and leaves the run available for a bounded rework loop or a human decision.

Can a non-technical stakeholder review the work?

Yes. Gate 1 includes a Mermaid interaction flow for every story, plus an OpenPencil UI design and PNG preview when a graphical component is present; the review console renders both in its document viewers.

Does ASTRA require LangGraph?

No. The bundled local runtime is the default. LangGraph is an optional peer runtime with parity tests.
